# Чек-лист подготовки релиза Supacon (Release Candidate v0.1.0-rc.1)

Настоящий документ фиксирует готовность версии-кандидата **Supacon v0.1.0-rc.1** и структурирует перечень вопросов, требующих решения и приёмки владельцем продукта (Михаилом).

---

## 1. Вопросы, ожидающие решения Михаила (Блокирующие релиз)

### 1.1. Боевой HTTPS и хостинг (Production Hosting & HTTPS)

Service Worker, Web App Manifest и Web Notifications в современных браузерах (Safari, Chrome, Firefox) имеют строгое платформенное ограничение: **они функционируют исключительно по протоколу HTTPS** (либо на `localhost`).

- [ ] **Выбор целевого origin / домена:**
  - Определение основного URL приложения (например, `app.supacon.org` или иной production-домен).
  - *Примечание:* согласно регламенту разработки, dev-окружение (`chat.ramdero.org`, порт 8787, VPS, DNS) не модифицировалось.
- [ ] **SSL/TLS сертификат:**
  - Наличие валидного доверенного сертификата (Let's Encrypt, Cloudflare SSL или сертификат хостинг-провайдера) с автоматическим продлением.
  - Принудительный редирект HTTP -> HTTPS (301 Permanent Redirect).
- [ ] **HTTP-заголовки веб-сервера (Nginx / Caddy / Cloudflare Pages):**
  - **Политика кэширования (Критично для PWA):**
    - `index.html` и `sw.js`: `Cache-Control: no-cache, no-store, must-revalidate` (чтобы браузер всегда проверял наличие новой версии Service Worker).
    - `assets/*` (файлы со статическими хэшами в имени): `Cache-Control: public, max-age=31536000, immutable`.
    - `manifest.webmanifest`: `Cache-Control: public, max-age=3600`.
  - **MIME-типы:**
    - `manifest.webmanifest` -> `application/manifest+json`.
    - `sw.js` -> `application/javascript`.
    - `*.woff2` -> `font/woff2`.
  - **Заголовки безопасности:**
    - `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; media-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'`
    - `X-Content-Type-Options: nosniff`
    - `Referrer-Policy: strict-origin-when-cross-origin`
- [ ] **Конфиденциальность:**
  - Подтвердить отсутствие внешних трекеров, счетчиков аналитики и CDN. Все шрифты (Literata, Manrope) поставляются локально в бандле.

### 1.2. Физическая приёмка на мобильных устройствах (Device Acceptance)

Эмуляторы DevTools не воспроизводят специфику физического взаимодействия, аппаратного энергосбережения и ограничений мобильных ОС. Необходима ручная верификация на реальных смартфонах.

#### iOS (Apple Safari / WebKit):
- [ ] **Установка PWA («На экран "Домой"»):**
  - Открыть в Safari, нажать «Поделиться» -> «На экран "Домой"» (Add to Home Screen).
  - Проверить иконку приложения (192×192 / 512×512) и название («Supacon»).
  - Запуск в standalone-режиме: отсутствие адресной строки и тулбара Safari.
- [ ] **Геометрия экрана и Safe Areas:**
  - Корректность отступов под «чёлку» / Dynamic Island сверху и индикатор Home снизу (`viewport-fit=cover`).
  - Интерактивные элементы не перекрываются системными жестами iOS.
- [ ] **Аудио звуков завершения (WebAudio):**
  - Проверить воспроизведение гонга/чаши/колокольчика в фокус-блоке. В Safari WebAudio требует первоначальной активации пользовательским тапом.
- [ ] **Screen Wake Lock (удержание экрана):**
  - На iOS 16.4+ проверить удержание экрана во время таймера фокус-блока (экран не должен гаснуть).
- [ ] **Виртуальная клавиатура:**
  - При вводе заметок в вечернем обзоре клавиатура не должна ломать верстку (`interactive-widget=resizes-content`).

#### Android (Google Chrome / Chromium):
- [ ] **Установка PWA (Install Prompt):**
  - Появление нативного баннера «Установить приложение» (соответствие PWA criteria).
  - Наличие маскируемых иконок (`maskable 192/512`) без белых полей на лаунчерах (Samsung, Pixel, Xiaomi).
- [ ] **Тактильный отклик (Haptics / Vibration API):**
  - Вибрация на фазах дыхания и слайдере осознанности (1–10).
- [ ] **Системная кнопка «Назад»:**
  - Навигация по hash-роутингу (`#/pause`, `#/today`, `#/settings`) без закрытия PWA.
- [ ] **Screen Wake Lock:**
  - Работа темного экрана фокус-блока без засыпания экрана устройства.

### 1.3. Предел дневника (localStorage Quota & Diary Limits)

- **Платформенное ограничение:**
  - Мобильный Safari (WebKit) и Chrome выделяют лимит **~5 МБ** на origin для `localStorage`.
- **Фактический расход памяти:**
  - Одна запись ритуала паузы в JSON занимает **~350–400 байт**.
  - 1 000 записей ≈ 350–400 КБ (с учетом бэкапа `supacon.v1.bak` ≈ 700–800 КБ).
  - 3 000 записей ≈ 1.1 МБ (с бэкапом ≈ 2.2 МБ).
  - 5 000 записей ≈ 1.8 МБ (с бэкапом ≈ 3.6 МБ — приближение к 5 МБ).
- **Реализованные механизмы защиты:**
  - При переполнении квоты (`QuotaExceededError`) данные в памяти не теряются.
  - Появляется заметный баннер ошибки с кнопкой мгновенной выгрузки JSON-файла («Скачать резервную копию»).
  - Ручной экспорт доступен в форматах JSON, CSV, Markdown, .ics.
- **Вопрос к Михаилу:**
  - Достаточен ли текущий предел в ~3 000–5 000 записей для релиза 7-дневной практики (MVP)?
  - *Рекомендация:* **Да, полностью достаточен.** 7-дневный протокол генерирует 30–70 записей (< 25 КБ). Пользователю понадобится более 2–3 лет непрерывной ежедневной практики, чтобы приблизиться к пределу. Дополнительно можно запланировать автоматическое предупреждение при превышении 1 000 записей.

### 1.4. IndexedDB (Пункт 5 бэклога: Multi-snapshot local backups)

- **Суть предложения из бэклога:**
  - Дополнение ключа `supacon.v1.bak` цепочкой скользящих еженедельных снапшотов в IndexedDB.
- **Анализ рисков и преимуществ:**
  - *Преимущества IndexedDB:* хранилище до сотен мегабайт, хранение истории снимков.
  - *Риски и недостатки:*
    - IndexedDB асинхронен и подвержен сбоям в мобильных браузерах (события `blocked`, ошибки версионирования при параллельных вкладках, агрессивная очистка в iOS при нехватке памяти).
    - `localStorage` синхронен, детерминирован, защищен 573 unit-тестами и не имеет состояний гонки при записи.
- **Вопрос к Михаилу:**
  - Включать ли IndexedDB в релиз v0.1.0 или оставить в бэклоге для v0.2+?
  - *Рекомендация команды:* **Оставить в бэклоге (не включать в v0.1.0).** Текущая модель (`localStorage` + синхронный `supacon.v1.bak` + аварийная выгрузка JSON) обеспечивает максимальную надежность и проверена на 100%.

## 3. План развёртывания после утверждения решений

1. Михаил утверждает решения по хостингу, лимиту дневника и статусу IndexedDB.
2. Проводится контрольное тестирование на 1 физическом устройстве iOS и 1 Android.
3. Команда выполняет финальный гейт под `flock /tmp/heavy-gate.lock` (`typecheck`, `test`, `build`, `test:e2e`).
4. Формируется релизный коммит и создается Pull Request в ветку `main`.
5. Артефакты сборки из `dist/` разворачиваются на целевой боевой HTTPS-хостинг.
